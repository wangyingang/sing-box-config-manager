# #51 恢复单集跟随最新来源

[#51](https://github.com/wangyingang/sing-box-config-manager/issues/51) 覆盖 [Spec #47](https://github.com/wangyingang/sing-box-config-manager/issues/47) 的 A6、A8 和 A11 的人工固定与恢复部分。以仓库根目录的统一验证入口运行常规检查、原生集成测试及固定官方 Release 验收。

| 场景 | 可观察结果 |
| --- | --- |
| OpenAI 从 B 回滚到 A 后恢复，最新 Release 仍为 B | 只检查 OpenAI，并重新验证和采用 B。保留 Anthropic 的人工固定及 Google DeepMind 的当前版本。上游请求直接读取最新 Release。 |
| 恢复决定提交后失去连接，尚未请求上游 | 从新目录读取到新控制修订、当前规则和待检查状态。首次检查失败时仍交付原规则，后续正常检查能成功更新。 |
| 自动任务已登记，随后人工固定并恢复 | 最早任务不能发布或激活。单分支和双分支模型都覆盖该竞争。 |
| Anthropic 已发布部分候选文件时恢复 OpenAI | OpenAI 立即检查最新 Release。Anthropic 可以从原 Release 和候选 ID 继续。 |
| 恢复已登记固定 Release 后断线，默认批次继续 | 批次沿用该 Release 并完成三集检查。 |
| 单集恢复与其他在途检查重叠，或兄弟集已跟随更新的 Release | 普通批次要求继续原操作，兄弟集不会被较旧的 Release 覆盖。 |
| 恢复决定落盘后断线，远端暂存了候选更新 | 原更新命令继续已固定的 Release，后续恢复命令沿用已保存的控制修订。 |
| 使用不同构建配置重新请求中断的恢复 | 新请求获得新的控制修订。旧配置的在途检查不能继续交付。 |
| 维护窗口内请求恢复 | 无法提交控制修订，也不会请求上游。 |
| 同一个 sing-box 1.14.4 进程经历 A、B、回滚到 A、检查暂停和恢复到 B | 同一稳定 URL 依次读取 A、B、A、B。Route 新请求和 DNS 新查询实际命中对应规则。使用同一个配置文件和发布快照。 |
| CLI 选择缺失、重复选择或恢复后检查失败 | 缺失和多集选择退出非零。单集失败返回逐集 JSON 和非零退出码。 |

恢复场景使用受控产物仓库和 Release 响应。客户端通过进程专用代理从本地 HTTPS 服务读取稳定地址。真实产物仓库上的写入、CDN 传播与生产启用属于其他验收范围。
