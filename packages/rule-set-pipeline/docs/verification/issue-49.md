# #49 人工固定与远端核实

本次验收使用隔离的 Git transport 和真实 sing-box 1.14.4。候选经过原生编译、解码、加载及字节校验。测试覆盖生产的双分支布局和验收的单分支布局，远端写入由测试 transport 承担。

| 验收 | 证据 |
| --- | --- |
| 三集均支持人工指定和历史回滚 | [配置化激活](../../test/integration/configured-activation.test.ts)与[配置化回滚](../../test/integration/configured-rollback.test.ts)依次对三集操作，比较稳定文件、激活记录及兄弟集状态。 |
| 固定状态与稳定规则一起提交 | 测试读取同一稳定提交，比较规则字节和控制状态。人工指定暂停自动激活。回滚同时暂停自动激活和重试。 |
| 指定当前版本更新控制修订 | 同一候选连续指定两次，文件摘要一致，控制修订变化。 |
| 校验失败保留原状态 | 不匹配的规则集、历史、订阅、候选证据或原生校验均在写入前拒绝。 |
| 从新目录核实操作 | 测试移除原目录，查询丢失回复、HTTPS 回读失败、本地回执失败和明确拒绝的操作。兄弟集推进稳定分支后，仍能定位原切换提交。同集新的人工决定使旧操作报告为已被替代。 |
| 写入遵守远端协调 | 两种分支布局均注入维护状态、代次或 journal head 变化。[GitHub transport 测试](../../test/activation-transport.test.ts)确认更新引用前绑定远端登记，且最后一次检查之后仍在途的稳定写入会阻止双分支维护状态变化。 |

执行 `node scripts/verify.mjs --out <新证据目录> --binary <1.14.4绝对路径>` 可复查常规检查及原生集成测试。实际 GitHub 产物分支写入与客户端 CDN 传播需要另行执行隔离验收。生产切换、自动检查、恢复与历史清理由其他工单处理。
