# Recipe 自动跟随已激活的系统规则版本

2026-11-03，Rule Set Pipeline 首个完整交付的设计确认：Recipe 选择系统规则集及用途，通过稳定的规则订阅入口自动跟随已激活版本，不提供固定规则产物版本的选项。规则候选通过验证和订阅兼容性检查后，才可显式激活。客户端按自身远程规则更新机制加载新版本，无需修改 Recipe 或重新发布配置。

这一选择用规则内容的持续更新，换取配置发布后不再固定运行时规则内容。后台仍保留不可变产物、Artifact Manifest、来源和验证记录，用于追溯与回滚。配置快照记录所引用的规则订阅契约及发布时验证证据，不宣称固定客户端此后加载的规则字节。

Recipe／Template 的系统规则绑定和 Compiler 接入契约随本次交付演进。Compiler 消费已验证的内存元数据，不下载规则，也不导入 Pipeline 运行时代码。稳定订阅的用途、格式、目标版本及能力约束必须在每次激活前检查，不能通过内容更新绕过既有兼容性校验。

首版使用 sing-box 原生远程规则更新与缓存机制，不开发额外客户端更新组件，不强制实际客户端的缓存设置或更新周期。已加载规则遇到后续下载或加载失败时继续使用旧规则；跨重启恢复依赖有效且已成功写入的持久缓存。

本决策是 Spec #1 完成后的契约演进。Spec #1 的原始需求、实现与验收历史保留。模板、节点和 Client Profile 的既有固定引用规则不因此改变。

具体交付范围与验收边界见[首个完整交付设计](../architecture/rule-set-pipeline-first-delivery.md)。

## 规则候选验证通过后的自动激活

`check-now` 和启用了更新的定时工作流共用检查流程。Pipeline 发现规则内容有有效变化后，会验证候选及其订阅兼容性。只有验证通过且该规则集允许自动激活时，Pipeline 才切换稳定入口。`update` 和 `rebuild` 只发布候选。

人工指定版本或回滚会暂停该集的自动激活。管理者可用 `resume` 解除人工固定，并立即检查该集的最新来源。客户端按自身更新机制从原稳定 URL 获取已激活版本，无需重新发布配置。[自动更新与人工控制 Spec #47](https://github.com/wangyingang/sing-box-config-manager/issues/47)
