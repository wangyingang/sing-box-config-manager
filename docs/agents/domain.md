# Domain docs

本仓库的领域文档采用 multi-context 布局，以支持计划中的 monorepo。上下文边界及具体目录随重构确定；package 与领域上下文不必一一对应。

## 探索前读取

- 根目录存在 `GLOSSARY-MAP.md` 时，先读取该索引，再读取与当前任务相关的上下文 `GLOSSARY.md`。
- 尚无 `GLOSSARY-MAP.md`、但根目录存在 `GLOSSARY.md` 时，读取根目录术语表。
- 从根目录 `docs/adr/` 读取与当前任务相关的全局 ADR。
- 按 `GLOSSARY-MAP.md` 中记录的路径，读取相关上下文的 ADR。

这些文件尚不存在时，直接继续工作，无需报告缺失或建议预先创建。由 `/domain-modeling` 在实际确定术语或决策时按需建立。

## 布局约定

- `GLOSSARY-MAP.md`：位于仓库根目录，记录各领域上下文的职责、术语表路径及 ADR 目录。
- `docs/adr/`：保存跨上下文的架构决策。
- 各上下文的 `GLOSSARY.md`：随对应代码存放。
- 各上下文的 `docs/adr/`：保存仅适用于该上下文的架构决策。

具体路径以索引和实际目录结构为准。移动上下文时，同步更新索引中的路径。

## 使用领域词汇

Issue 标题、设计建议、诊断假设、测试名称等输出涉及领域概念时，使用相关术语表定义的名称。

需要的概念尚未收录时，先判断是否误用了项目之外的术语；确有缺口时，将其记录为 `/domain-modeling` 的待澄清项。

## 处理 ADR 冲突

建议或实现与已有 ADR 冲突时，明确指出对应 ADR、冲突内容及重新讨论的理由，再推进决策变更。
