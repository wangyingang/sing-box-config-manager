# Rule Set Pipeline 首个完整交付设计

设计确认日期：2026-11-03。本页保留设计基线；分阶段交付状态以 [Spec #14](https://github.com/wangyingang/sing-box-config-manager/issues/14) 和子工单为准。[#15 本地 JSON 构建验收](../../packages/rule-set-pipeline/docs/verification/issue-15.md)记录已交付的输入与转换范围。

本设计承接 Spec #1 已完成的 Compiler 与固定产物契约，新增真实规则生产、候选发布、激活、回滚及客户端自动更新闭环。规则订阅决策见 [ADR 0006](../adr/0006-follow-active-rule-subscriptions.md)。Spec #1 的原始需求与验收历史不作改写。

## 交付目标

以 V2Fly domain-list-community 官方 Release 的 dlc.dat_plain.yml 为输入，只提取 category-ai-!cn，完成：

人工查询 Release → 固定输入身份并校验摘要 → 提取列表 → Rule IR →
用途投影 → JSON／SRS → 内容验证与实际字节摘要 →
不可变候选产物及 Manifest → 显式激活稳定入口 →
Compiler 生成订阅引用 → 真实 sing-box 自动更新与失败保留验证。

首版不迁移全部规则集，也不以 Blackmatrix7 迁移为前置条件。

## 来源固定与处理状态

正常更新由人工触发，查询官方 latest Release。与成功处理记录比较，没有新版本时跳过资产下载、解析和转换。

发现新版本后固定 Release ID、tag、对应源码 commit 和资产身份。后续请求使用该固定 Release，不在处理过程中再次解析 latest。源码 commit 从 tag 引用解析，不能用浮动分支的当前 HEAD 代替。

下载同一 Release 中的 dlc.dat_plain.yml 和 dlc.dat_plain.yml.sha256sum，核对摘要文件中的文件名及实际 YAML 字节摘要。记录 repository、Release ID、tag、源码 commit、资产 ID、地址、实际输入摘要及构建工具版本。已固定输入的资产身份或内容发生变化时明确失败，不覆盖原记录。

成功处理记录、已验证候选和当前激活版本分别管理。只有候选已完成规定验证及远程回读，才记录该 Release 处理成功。处理失败不标记成功，允许重试。激活失败可重试已有候选，不要求重新转换。

保留显式重建同一 Release 的维护入口。重建仍校验固定输入，记录新的构建身份并产生候选，不覆盖历史版本，不自动激活。正常更新的无新版本跳过行为保持不变。

## 输入适配与转换语义

Include 展开、attribute 筛选、affiliation、官方排序与去冗余由 V2Fly 官方构建程序负责。本项目不解析原始来源，不扫描全来源的 affiliation。

输入读取与后续转换分离。首版使用 YAML；未来可替换为 DAT 解码而保持下游边界。

YAML 中只选择目标列表。目标列表必须唯一、非空，声明 length 必须与 rules 数量一致。整个 YAML 损坏，或目标列表存在未知类型、非法值及无法无歧义解析的记录，均使候选构建失败。

官方 plain 字符串中的属性尾部仍需解析。domain、full、keyword 的匹配值与属性分离后，保留规则，不执行本地属性筛选。regexp 保留表达式；出现字面 :@ 时明确失败，因为官方导出格式无法区分正则内容与属性尾部。此限制也拒绝带属性的 regexp。

四种类型映射如下：

| 官方类型 | Rule IR／sing-box 字段 | 匹配语义 |
| --- | --- | --- |
| domain | domain_suffix | 域名本身及其子域；不添加前导点 |
| full | domain | 完整域名精确匹配 |
| keyword | domain_keyword | 子串匹配，不要求 label 边界 |
| regexp | domain_regex | 保留表达式及锚点语义，由目标 Go 引擎验证 |

保留官方已规范化的值。不额外执行 IDNA 转换、去尾点、正则转小写或表达式改写。YAML 字符串只按 YAML 规则解码一次。

Rule IR 表达无动作的独立匹配谓词，集合采用 OR 语义。首版生产输入覆盖上述四种域名谓词；合成 IR 另覆盖目标 ip_cidr，以验证 IP 投影。其余旧 Pipeline 字段不因通用草案存在而自动纳入本次实现。

只对同类型且值相等的 term 去重，按固定类型顺序和值顺序排序。不做子域覆盖消除、CIDR 聚合或正则改写。

Conversion Report 记录目标列表输入条数、成功转换数、不支持数、无效数、重复数、输出 term 数、各类型和用途计数及诊断位置。属性移除不计为规则丢弃。失败报告不能被当作部分成功产物发布。

正常成功路径满足：

inputCount = convertedCount
outputTermCount = convertedCount - duplicateCount

失败路径分别统计不支持与无效记录，并报告文件或列表级错误；部分计数不构成发布依据。

## 用途投影与产物

Route 使用全部适用 term；DNS 请求使用域名谓词；DNS 响应只使用目标 ip_cidr。

category-ai-!cn 的纯域名产物供 Route 与 DNS 请求复用。DNS 响应用途标记为 unavailable: empty，不生成空文件，也不能被绑定。合成输入验证纯 IP 和域名／IP 混合投影。

输出 Source Format v4 JSON 和由真实 sing-box 1.14.4 编译的 SRS。二者分别计算实际文件字节 SHA-256，记录字节数和 term 数。编译、解码和真实加载验证共同检查内容；不能仅凭 sing-box check 成功认定远程内容正确。

同一固定输入、列表、转换策略与工具版本必须产生相同 JSON／SRS 字节。时间等运行记录不参与规则文件内容。构建身份与输入来源、转换器、目标 binary 和契约版本关联。

## 不可变候选与稳定规则订阅

实现位于当前 monorepo 的 packages/rule-set-pipeline，采用 TypeScript、Node.js 和现有 pnpm 工具链，通过子进程调用固定的 sing-box 1.14.4。

公开产物存放于 wangyingang/sing-box-rule-artifacts。候选文件使用完整 commit 固定的 HTTPS 地址，保留 Manifest、来源、转换报告和验证记录。不可变文件与引用它们的清单按先后顺序发布，避免自引用地址或摘要的循环定义。

上传后重新下载实际文件，校验摘要、字节数和内容。候选验证完成不等于激活。

稳定规则订阅使用仓库固定路径，客户端默认消费 SRS。显式激活前检查候选完整性、非空内容及订阅的用途、格式、目标版本和能力约束。通过后，以一次 Git 提交更新稳定文件和激活记录，并检查预期旧状态，拒绝覆盖并发激活。

构建或验证失败不得更新稳定入口。激活请求结果不确定时先核实远端状态，不能直接宣称旧版本未变。GitHub 缓存及客户端轮询可能造成传播延迟，不承诺所有设备同时切换，也不承诺多个文件在客户端作为一个批次原子更新。

回滚重新激活符合订阅契约的历史版本，不修改历史产物，不倒退成功处理记录。旧版本保留用于追溯和回滚，本次不实现自动清理策略。

首版通过本地 CLI 完成检查、候选发布、激活、重建与回滚。现有 CI 纳入相关检查；不新增生产发布 workflow 或定时任务。

## Recipe／Compiler 契约演进

Recipe 只选择系统规则集及用途，保留必要的本地 tag 和既有 HTTP client 引用，不提供固定产物版本、任意 URL、摘要或能力覆盖入口。Template 中的系统规则绑定遵循相同订阅边界。

Artifact Manifest 继续描述不可变版本产物。新增规则订阅契约描述稳定入口及其兼容性约束；不可变清单的摘要不能被解释为未来可变入口内容的摘要。

可信宿主向 Compiler 提供已验证的订阅契约及相关证据。Compiler 保持纯函数边界，不访问网络、不执行 Pipeline；继续检查用途、策略位置、资源引用及 Profile 能力。必要的 Recipe／Compiler 不兼容契约调整须显式升级版本，不能让现有 schemaVersion 悄悄改变含义。

编译结果引用稳定入口。新规则激活后，已有配置无需重新发布。配置快照固定配置内容、订阅契约和发布时验证证据，不固定客户端此后加载的规则字节。

订阅兼容性门禁适用于后续每次激活，不能只验证当前样本。已有 Spec #1 的固定产物行为保留为历史验收，不把旧测试直接改名解释为自动跟随能力。

## 客户端更新与失败边界

使用 sing-box 原生远程规则更新与缓存机制，不开发额外客户端组件。更新周期和缓存由实际客户端配置决定，本项目不统一强制设置。

已成功加载规则后，后续下载、读取、解析或兼容性校验失败时继续使用旧规则。验收持久缓存成功写入后，断网重启仍可使用缓存规则。

接受原生能力限制：客户端不额外验证 Manifest 摘要；合法但错误的内容不能依靠客户端摘要校验拦截；缓存写入失败不会回滚已生效的内存规则；无有效缓存的首次启动、缓存损坏等情形不承诺旧规则可用。合法空内容必须在发布端门禁拒绝。

## 验收边界

| 范围 | 必需证据 |
| --- | --- |
| 真实来源 | 固定 Release 的 YAML 与摘要实际下载并核对；记录 tag 对应源码 commit 和资产身份 |
| 无新版本 | 重复正常检查不会下载资产、解析或转换 |
| 失败重试 | 处理失败不记录成功；候选激活失败可独立重试 |
| 真实转换 | 使用 Release 20261102130044 的 category-ai-!cn；来源为 214 条，包含 domain、full、regexp 及属性尾部；报告无静默丢弃 |
| 合成转换 | 四种类型、属性尾部、regexp 转义与 :@ 歧义、未知类型、坏 YAML、缺失／重复／空列表及错误 length 的正反例 |
| 匹配语义 | 验证 domain 的 apex／子域／相似后缀反例、full 精确匹配、keyword 子串及 regexp 锚点和大小写行为 |
| 投影 | 纯域名文件复用于 Route／DNS 请求；DNS 响应不可用；合成 IP 与混合 IR 正确投影 |
| 原生产物 | 真实 1.14.4 编译、解码及加载；JSON／SRS 语义对应，分别校验实际字节摘要 |
| 确定性 | 独立重复构建的 JSON／SRS 字节一致；输入枚举顺序不改变规范化结果 |
| 发布 | HTTPS 上传与回读证据；摘要、加载、空内容或订阅兼容性失败不激活 |
| Compiler | 新绑定生成稳定入口；拒绝任意 URL、空用途、错误消费位置及能力失配；既有回归门禁通过 |
| 自动更新 | 同一份生成配置与同一运行实例，在激活后通过新请求的实际 Route／DNS 行为证明新规则生效 |
| 客户端失败 | 注入网络／HTTP 错误、截断和坏内容等失败，实际匹配仍使用旧规则；故障解除后恢复更新 |
| 缓存 | 受控实例成功写入缓存后断网重启，实际匹配仍使用缓存规则 |
| 回滚与重建 | 历史版本重新激活后行为恢复；同一 Release 显式重建不覆盖历史且不自动激活 |

真实官方样本承担来源到产物、发布及 Compiler 接入的端到端验收。受控合成版本补足可重复的规则变化与故障注入，不能用合成来源代替真实 Release 验收。

受控 sing-box 1.14.4 实例可启用缓存并缩短更新周期。验收观察新请求的 Route／DNS 匹配或最终行为，不以日志、HTTP 200 或已有连接作为唯一证据。这些测试设置不成为实际客户端的统一要求。

- V2Fly 原始来源的 Include、attribute 筛选与 affiliation 实现及其解析器测试。
- 全仓库迁移、多个根列表的批量迁移、Blackmatrix7 迁移。
- DAT 解码实现、其他输入源及未列明的 Rule IR 类型。
- 子域覆盖优化、CIDR 聚合、正则改写和跨来源语义合并。
- 固定产物版本的 Recipe 产品选项。
- 额外客户端更新组件、客户端 Manifest 摘要校验。
- 统一客户端缓存或更新频率、全部设备同步更新及固定完成时限。
- 生产发布 GitHub Actions、定时采集、新 Web 管理界面及配置订阅授权服务。
- 旧 sing-box-geosite 自动化迁移、实际设备全面验收及业务连通性证明。
- 产物自动清理和更广泛的部署平台选择。

regexp 中字面 :@ 的歧义是首版已知限制，遇到时明确失败。首次启动无旧缓存、缓存损坏及持久化失败等原生边界不扩展为本项目的无条件恢复保证。
